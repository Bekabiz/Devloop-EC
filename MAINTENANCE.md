# DEVELOP EC — TECHNICAL REFERENCE & MAINTENANCE GUIDE

Last verified against the codebase: August 2026.
Stack: React 18 + Vite 5 + TypeScript, GSAP/ScrollTrigger, Lenis, React Three Fiber, one Vercel serverless function.

---

## 1. ENVIRONMENT VARIABLES

The project reads exactly ONE environment variable:

- `OPENAI_API_KEY` — the OpenAI API key for the chat assistant. Read at runtime (never at build time) in `api/chat.js` (line with `process.env.OPENAI_API_KEY`). Set it in the Vercel dashboard (Settings → Environment Variables, all environments) and, for local testing with `vercel dev`, in `.env.local` at the repo root. It is never committed, never sent to the browser, never logged.

Nothing in `src/` reads any environment variable (no `import.meta.env` usage). There are no other secrets.

`.gitignore` blocks `.env`, `.env.local`, `.env*.local`, `.vercel`, `node_modules`, `dist`.

---

## 2. THIRD-PARTY SERVICES

1. **Vercel** — hosting, CDN, and the `/api/chat` serverless function. Deploys automatically on every push to the `main` branch of github.com/Bekabiz/Devloop-EC. If it stops: the whole site is down. Hobby (free) tier: fair-use bandwidth and function-invocation limits; fine for this traffic level.

2. **OpenAI API** — powers the chat assistant. Called only from `api/chat.js` (endpoint `https://api.openai.com/v1/chat/completions`, model `gpt-4o-mini`). If it stops or the key is revoked/unfunded: the chat shows its friendly error with the phone number; nothing else on the site is affected. Paid per token (no free tier) — `gpt-4o-mini` is very cheap; the rate limits in section 8 cap worst-case spend.

3. **FormSubmit (formsubmit.co)** — delivers contact-form submissions to the private inbox. Called from `src/components/home/Contact.tsx` (`DELIVERY_ENDPOINT` constant, `https://formsubmit.co/ajax/adamopoulos.gm@gmail.com`). If it stops: the form shows its error message with the public email address; visitors can still email directly. Free tier; required a one-time activation click sent to the delivery inbox. Note the split: the DISPLAYED email everywhere is `adamopoulosandpartners@gmail.com`; the DELIVERY address (never shown) is `adamopoulos.gm@gmail.com`.

4. **Google Fonts** — Jost and Cormorant Garamond, loaded via `<link>` in `index.html`. If it stops: the site falls back to system fonts (ugly but functional). Free, no limits. If you ever want zero external dependencies, self-host the woff2 files and update `index.html` plus the CSS `--font`/`--serif` variables.

5. **GitHub** — source of truth for code AND all media sources (the repo is ~1 GB+ because raw 4K sources live in `assets/`). Vercel builds from it.

No analytics, no cookies service, no CMS, no database.

## 4. BUILD AND DEPLOY

- Node: any modern LTS works; the site was built and verified on **Node 22** (Vite 5 requires ≥18). No `engines` field is enforced.
- Install: `npm install`
- Local dev: `npm run dev` (Vite on :5173). NOTE: plain Vite dev has NO `/api/chat` — the chat will show its styled error. To test the chat locally use `vercel dev` with `OPENAI_API_KEY` in `.env.local`.
- Production build: `npm run build` (runs `tsc -b` type-check, then `vite build` into `dist/`)
- Preview a build: `npm run preview`
- Deploy: **push to `main` on GitHub** — Vercel builds and deploys automatically. There is no manual deploy step.

Non-obvious build facts:
- Media in `public/media/` is committed, NOT generated during the Vercel build. The ffmpeg pipeline runs locally (section 5); Vercel just copies `public/`.
- `api/_knowledge.js` is committed generated code. After editing `src/data/chatbot-knowledge.md`, run `node scripts/gen-knowledge.mjs` and commit both files, or the chatbot will keep the old knowledge.
- `public/sitemap.xml` is static. If a project slug changes or one is added, update it (section 9).

## 5. THE MEDIA PIPELINE

One script: `scripts/process-media.sh` (requires ffmpeg on your machine).

What it produces from `assets/source/`:
- Project photos → `NN.webp` (1920w, q82) + `NN-m.webp` (960w, q78) per photo
- Grid thumbnail → `thumb.webp` (1200×800 center-crop) from photo 01 by default; per-project overrides live in the `THUMB_SRC` map at the top of the script (currently: katakolo-terraces uses photo 03 — a client choice)
- Project videos → h264, CRF 23, max 1920w, audio stripped, `+faststart`, keyframe every second; `poster.jpg` = exact first frame (this exactness prevents a visible jump on load)
- Hero → desktop 1920w CRF 23 + a 720×1280 9:16 center-crop at CRF 21 for phones; first-frame posters for both
- Construction gallery → 30 × 1024w webp, plus 1600w "hd" copies of the 12 photos used by the mobile sequence (the list of 12 in the script must match `MOBILE_SEQ` in `src/components/home/Cinematic.tsx`)
- Team portraits, logo copies, and the 1200×630 social-share image

How to run:
- Everything: `bash scripts/process-media.sh`
- One project only: `bash scripts/process-media.sh <slug>`
- Dry-run to a scratch folder: `MEDIA_OUT=/tmp/media bash scripts/process-media.sh`

When the client sends replacement photos/videos: drop them into `assets/source/projects/<slug>/` with the correct numbered name (overwriting), move the old file to `assets/archive/<slug>/`, run the script for that slug, check the result locally, commit `assets/` + `public/media/` together, push.

## 6. CONTENT EDITING — WHERE EVERYTHING LIVES

- **Project names, locations, types, statuses, years, services, descriptions, photo captions** (both languages): `src/content/projects.ts`. Each project has an `i18n.en` and `i18n.gr` block. Grid order = array order (client rule: biggest project first). The odd 15th project automatically renders centered on the last grid row.
- **Every other piece of site text** (nav, hero, statement, services, about, team, contact, chat UI, footer, privacy policy): `src/content/en.json` and `src/content/gr.json` — same structure, edit both.
- **Chatbot knowledge**: `src/data/chatbot-knowledge.md`, then run `node scripts/gen-knowledge.mjs` (see section 8). The chatbot's project list must be kept in sync with `projects.ts` manually.
- **Contact details** (email shown, phone, hours, both office addresses): the `contact.info` block in `en.json`/`gr.json`. The same facts also appear in: the JSON-LD block in `index.html`, `src/data/chatbot-knowledge.md`, the chat system prompt example in `api/chat.js`, and the privacy policy sections in both JSON files — update all of them.
- **Footer legal line** (ΑΦΜ/ΓΕΜΗ): `footer.legal` in `en.json`/`gr.json`.
- **Team members**: `team.members` in both JSON files (name, role, photo path). Portrait sources in `assets/source/team/`.
- **Statuses**: statuses are free text per language (e.g. "Under Construction" / "Υπό κατασκευή"), so a project moving to completed means editing both language blocks in `projects.ts`.

## 7. ADDING A 16TH PROJECT — STEP BY STEP

1. Create `assets/source/projects/<new-slug>/` with `01.png … 06.png` (order: first 3 exteriors, then details; photo 01 is the grid card unless overridden) and `video.mp4` (the 4-second Kling clip). Slug: lowercase-hyphenated, unique.
2. Run `bash scripts/process-media.sh <new-slug>` → creates `public/media/projects/<new-slug>/`.
3. Add the project object to `src/content/projects.ts` — copy an existing entry as a template; fill `slug`, `year`, `photoCount`, and full `en` + `gr` text (name must be distinct from all 15 existing names — client rule). Insert it at the position matching its size (biggest first).
4. Add the project line to `src/data/chatbot-knowledge.md` (section "The 15 projects" — bump the count) and run `node scripts/gen-knowledge.mjs`.
5. Add a `<url>` entry for `/projects/<new-slug>` to `public/sitemap.xml` (copy an existing block, keep the three hreflang lines, set lastmod).
6. `npm run build` locally to confirm the type-check passes, click through the new page in `npm run preview`.
7. Commit everything (sources + processed media + code), push to `main`.

With 16 projects the grid becomes 8 full rows (the centered-last-card styling only activates on odd counts — no action needed either way).

## 8. THE CHATBOT

- **Route**: `api/chat.js` — a single Vercel serverless function. The browser widget (`src/components/chat/ChatPanel.tsx`) POSTs `{ messages, lang }` to `/api/chat`; the function calls OpenAI and returns `{ reply }`. The browser never talks to OpenAI.
- **System prompt**: the `SYSTEM_PROMPT` constant in `api/chat.js`. Helpfulness-first (answer anything about the company/construction; refuse only clearly unrelated topics), strict plain-prose formatting (no markdown, no lists, no long dashes), bilingual, "we/our team" voice, never invents prices or timelines.
- **Knowledge base**: written in `src/data/chatbot-knowledge.md`, injected into the prompt via the generated `api/_knowledge.js`. EDIT THE MARKDOWN, then `node scripts/gen-knowledge.mjs`, commit both.
- **Model**: the `MODEL` constant at the top of `api/chat.js` (`gpt-4o-mini`). Upgrade path: change that one string to `gpt-4o`. `MAX_TOKENS` (400) and `TEMPERATURE` (0.4) sit next to it.
- **Rate limits**: the `LIMITS` object in `api/chat.js` — 12 user messages per session, 30/hour and 100/day per IP, 1.5 s minimum between messages per IP, 500-char message cap, history capped at the last 10 messages. Store is in-memory per function instance (resets on cold start — accepted trade-off; swap for Vercel KV if abuse ever appears). The widget also enforces the 12-message session cap client-side (`MAX_USER_MESSAGES` in `ChatPanel.tsx`).
- **Other defences**: origin check (only developec.gr / *.vercel.app / localhost may call the endpoint), an off-topic keyword pre-check, `cleanReply()` which strips markdown/asterisks/list markers/long dashes from every reply, and friendly bilingual error messages for every failure path (upstream errors are logged server-side only, never shown).
- **Widget UI**: launcher in `src/components/chat/ChatWidget.tsx` (always loaded, tiny); the panel `ChatPanel.tsx` is a lazy chunk loaded on first click. UI strings under `chat` in the language JSONs, styles in `global.css` under "Chat widget".

## 9. KNOWN LIMITATIONS AND GOTCHAS

- **OG tags for project pages**: `src/lib/seo.tsx` updates title/canonical/OG tags per route at runtime. Google (which executes JS) sees them; WhatsApp/Facebook scrapers do NOT execute JS, so shared project links preview with the site-level card from `index.html`, not the per-project one. Fixing this fully requires prerendering or an edge function that serves bot-specific HTML.
- **`?lang=` URLs**: the site is a single-URL SPA; language lives in localStorage. For the sitemap's hreflang entries to resolve, `src/lib/i18n.tsx` also accepts `?lang=en|gr` on load (URL param wins over localStorage once, then is persisted). There are no separate `/el/` routes.
- **iOS hero autoplay**: React never serializes the `muted` prop as an HTML attribute, which makes iOS Safari refuse autoplay and show a native play button. The hero video is therefore injected via `dangerouslySetInnerHTML` in `src/components/home/Hero.tsx` with literal `autoplay muted playsinline webkit-playsinline` attributes, plus CSS that hides the webkit start-playback button (top of `global.css`), plus a play() retry. If you ever rewrite the hero, keep all three.
- **Video posters must be the exact first frame** (`-frames:v 1`, no `-ss`) or there is a visible jump when playback starts.
- **`position: sticky` broke** under an `overflow-x: hidden` ancestor on mobile; the mobile photo sequence therefore uses a GSAP `pin` instead of CSS sticky (`Cinematic.tsx`). Don't "simplify" it back to sticky.
- **ScrollTrigger + dynamic heights**: the Cinematic section swaps between a 420 vh 3D section (desktop) and the mobile sequence after mount, which changes page height; `ScrollTrigger.refresh()` is called after the swap. If you add sections that resize after mount, refresh again or below-the-fold reveals will compute wrong start positions and appear "stuck invisible".
- **The 30-photo gallery order** is defined in `src/components/home/cinematicOrder.ts` (biggest projects first, construction last) and refers to file numbers in `public/media/cinematic/`. The 12-photo mobile subset (`MOBILE_SEQ` in `Cinematic.tsx`) must have matching 1600w files in `cinematic/hd/` (the pipeline's hd list must be kept in sync).
- **Statement word animation**: the headline is split into per-word inline-block spans; the space must live as a text node BETWEEN spans (inline-block swallows trailing spaces). Preserved in `Statement.tsx` — don't restructure casually.
- **No long dashes anywhere**: a hard client rule for all site copy and chatbot replies (the API strips them as a safety net). Keep new copy dash-free.
- **Two emails**: displayed vs delivery (section 2). Never show `adamopoulos.gm@gmail.com` in the UI.
- **Chat on `npm run dev`**: no serverless runtime, so `/api/chat` 404s and the widget shows its error — this is expected; use `vercel dev` or the deployed site to test chat.
- **The repo carries ~1 GB of raw sources** in `assets/` — clones are slow; use `git clone --depth 1` when you only need to work on code.
- **Fresh media never appears?** Check you edited `assets/source/` AND ran the pipeline AND committed `public/media/` — the site serves only `public/media/`.

## 10. CONFIGURATION FILES

- **vercel.json** — two things: (1) a rewrite of every path to `/index.html` so SPA routes like `/projects/<slug>` work on direct load/refresh (Vercel checks real files and `/api/*` functions first, so media and the chat endpoint are unaffected); (2) `Cache-Control: public, max-age=31536000, immutable` on `/media/*` — media is cached hard, so a REPLACED image with the same filename can look stale for returning visitors; cache-bust by changing the filename if that ever matters.
- **vite.config.ts** — standard React plugin plus `manualChunks` splitting `three`/`@react-three/fiber` and `gsap` into their own bundles; three.js only downloads when the desktop 3D section approaches the viewport.
- **tsconfig.json** — strict TypeScript over `src/` only. `api/` is plain JavaScript on purpose (Vercel runs it directly; it is not part of `tsc -b`).
- **index.html** — meta description, canonical, OG/Twitter tags, JSON-LD Organization schema (contains the public email, phone, both addresses — keep in sync with content edits), font preconnect/stylesheet, and two media-query `<link rel="preload" as="video">` tags so the correct hero variant starts downloading before React boots.
- **.gitattributes** — line-ending normalization only.
